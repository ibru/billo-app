# Billo App Localization Development Plan

## Executive Summary

This document outlines a comprehensive plan to make the Billo app fully localizable using Apple's String Catalogs (`.xcstrings`). The codebase has partial localization (94 `String(localized:)` usages) but approximately **170+ strings** across **25+ files** need attention, including critical blockers around ordinal suffixes, recurrence descriptions, and accessibility strings.

---

## Key Decisions Required Before Implementation

### 1. Key Strategy
**Decision needed:** English-as-key vs stable keys

| Approach | Pros | Cons |
|----------|------|------|
| **English-as-key** (current pattern) | Readable code, self-documenting, no key mapping needed | Keys change if English text changes, harder to track |
| **Stable keys** (`"greeting.user"` + `defaultValue:`) | Keys never change, easier translation management | More verbose, requires key naming convention |

**Recommendation:** Continue with English-as-key for consistency with existing 94 usages, but establish a rule: once a string exists in the catalog, its English key should not change.

### 2. When to Use Each Localization API

| Context | Use This | Example |
|---------|----------|---------|
| SwiftUI Text views | `Text("Label")` | Text literals are auto-localized by SwiftUI |
| Computed strings / properties | `String(localized: "Label")` | Enum `displayName`, error messages |
| Format strings with arguments | `String(localized: "\(count) items")` | Plurals, interpolated values |
| Attributed strings | `AttributedString(localized:)` | Styled text |
| Passing to non-SwiftUI APIs | `String(localized:)` | Accessibility labels, notifications |

### 3. Pluralization Strategy
**Use String Catalogs native plural support** — NOT stringsdict.

String Catalogs (`.xcstrings`) can define plural variants directly. When you write:
```swift
String(localized: "\(count) bills due in \(days) days")
```
The String Catalog editor lets you define variants for `zero`, `one`, `two`, `few`, `many`, `other` per language.

## Phase 0: Infrastructure Setup

### 0.1 Create the String Catalog
The `.xcstrings` file must be **manually created** — it is NOT auto-generated by the build.

**Steps:**
1. In Xcode: File → New → File → String Catalog
2. Name it `Localizable.xcstrings`
3. Add it to the Billo target
4. Build the project — Xcode will populate it with extracted strings from `String(localized:)` and `Text()` views

### 0.2 Configure Export/Import Workflow
For translation workflow:
1. Product → Export Localizations → select languages
2. Send `.xcloc` files to translators
3. Product → Import Localizations → import completed translations

## Phase 1: Critical Blockers (Locale-Sensitive Grammar)

These issues cannot be localized with simple string wrapping — they require architectural changes.

### 1.1 Ordinal Suffixes (st/nd/rd/th)

**Files affected:**
- `Billo/Models/BillModel.swift:153-160`
- `Billo/Features/BillEdit/RepeatIntervalPicker.swift:77-84`

**Current code (duplicated in both files):**
```swift
private func daySuffix(_ day: Int) -> String {
    switch day {
    case 1, 21, 31: return "st"
    case 2, 22: return "nd"
    case 3, 23: return "rd"
    default: return "th"
    }
}
```

**Problem:** English-only ordinal rules. French uses "1er, 2e, 3e", German uses "1., 2., 3.", etc.

**Solution:** Use Foundation's locale-aware ordinal formatting:
```swift
private func ordinalDay(_ day: Int, locale: Locale = .current) -> String {
    let formatter = NumberFormatter()
    formatter.numberStyle = .ordinal
    formatter.locale = locale
    return formatter.string(from: NSNumber(value: day)) ?? "\(day)"
}
```

### 1.2 Recurrence Description

**File:** `Billo/Models/BillModel.swift:91-110`

**Current code:**
```swift
var recurrenceDescription: String? {
    guard let rule = bill.recurrenceRule else { return nil }

    let frequencyPrefix = rule.frequency == 1 ? "" : "Every \(rule.frequency) "

    switch rule.pattern {
    case .weekly:
        if let day = rule.dayOfWeek {
            return "\(frequencyPrefix)week(s) on \(day.displayName)"
        }
        return "\(frequencyPrefix)week(s)"
    case .monthly:
        if let day = rule.dayOfMonth {
            return "\(frequencyPrefix)month(s) on the \(day)\(daySuffix(day))"
        }
        return "\(frequencyPrefix)month(s)"
    case .yearly:
        return "\(frequencyPrefix)year(s)"
    }
}
```

**Problems:**
1. Hardcoded English words: "Every", "week(s)", "month(s)", "year(s)", "on", "on the"
2. Uses English ordinal suffixes
3. Word order assumptions (subject-verb-object) don't work in all languages

**Solution:** Use `RelativeDateTimeFormatter` where possible, or create structured localized strings:
```swift
var recurrenceDescription: String? {
    guard let rule = bill.recurrenceRule else { return nil }

    switch rule.pattern {
    case .weekly:
        if rule.frequency == 1 {
            if let day = rule.dayOfWeek {
                return String(localized: "Weekly on \(day.displayName)")
            }
            return String(localized: "Weekly")
        } else {
            if let day = rule.dayOfWeek {
                return String(localized: "Every \(rule.frequency) weeks on \(day.displayName)")
            }
            return String(localized: "Every \(rule.frequency) weeks")
        }
    case .monthly:
        let ordinalDay = ordinalDay(rule.dayOfMonth ?? 1)
        if rule.frequency == 1 {
            return String(localized: "Monthly on the \(ordinalDay)")
        } else {
            return String(localized: "Every \(rule.frequency) months on the \(ordinalDay)")
        }
    case .yearly:
        if rule.frequency == 1 {
            return String(localized: "Yearly")
        }
        return String(localized: "Every \(rule.frequency) years")
    }
}
```

### 1.3 Date Format Strings

**File:** `Billo/Utilities/BillsListSections.swift:217-219`

**Current code:**
```swift
let dateFormatter = DateFormatter()
dateFormatter.dateFormat = "MMMM yyyy"
let periodLabel = dateFormatter.string(from: referenceDate)
```

**Problem:** Hardcoded format string. Different locales expect different orderings (e.g., "yyyy年M月" in Japanese).

**Solution:**
```swift
let dateFormatter = DateFormatter()
dateFormatter.setLocalizedDateFormatFromTemplate("MMMM yyyy")
let periodLabel = dateFormatter.string(from: referenceDate)
```

### 1.4 Weekday Display Names

**File:** `Billo/Models/RecurrenceRule.swift` — `Weekday.displayName`

**Current code:**
```swift
var displayName: String {
    switch self {
    case .sunday: return "Sunday"
    case .monday: return "Monday"
    // ... hardcoded English
    }
}
```

**Solution:** Use Foundation's Calendar API:
```swift
var displayName: String {
    Calendar.current.weekdaySymbols[self.rawValue - 1]
}
```

### 2.6 Notification Pluralization
**File:** `Billo/Features/Notifications/Models/NotificationContentBuilder.swift:64-71`

**Current code:**
```swift
func digestTitle(billCount: Int, lookaheadDays: Int) -> String {
    let billsText = billCount == 1 ? "bill" : "bills"
    let daysText = lookaheadDays == 1 ? "day" : "days"
    return String(localized: "\(billCount) \(billsText) due in next \(lookaheadDays) \(daysText)")
}
```

**Problem:** Hardcoded English pluralization bypasses the localization system.

**Solution:** Let String Catalog handle pluralization:
```swift
func digestTitle(billCount: Int, lookaheadDays: Int) -> String {
    String(localized: "\(billCount) bills due in next \(lookaheadDays) days",
           comment: "Notification digest: use plural rules for 'bills' and 'days'")
}
```

Then in the String Catalog, configure plural variants for each language.
